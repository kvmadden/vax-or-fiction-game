# How this round was built

Kevin designed Vax or Fiction and its question bank. He evaluates the content as the pharmacist on the project. AI coding tools assisted with the runtime, tests and this evidence workflow. The source mapping and narrowed explanations in this change are AI-assisted drafts. Kevin has not yet performed the clinical review of this public snapshot.

The showcase uses the eight existing influenza question records. It adds no bank records. The full bank still contains 150 unique records and 180 deck appearances. The other 142 records are outside this content audit and remain unreviewed. The selected round has eight question appearances, eight supporting claims and 36 factual text appearances. Repeated explanations and closing summaries are appearances of the same claims, not new independent evidence.

The content pipeline saves normalized public CDC prose, exact character spans, SHA-256 hashes, retrieval dates, page dates and rights notes. Offsets refer to UTF-8 text decoded as Unicode characters in the committed normalized snapshot. The saved text joins visible HTML text and collapses whitespace within each line. It excludes script and style content. It is a source snapshot, not a rendering of the original page.

The preexisting older-adult citation opened a 2022 influenza-composition report. The selected round now uses the current CDC interim influenza guidance. The Pink Book warns that seasonal recommendations may be outdated. This round uses it only for the minor-illness statement. Current CDC key facts, heart-disease and antiviral pages supply the claims that the old citations did not directly support. Only selected CDC government prose is quoted. Photos, logos, third party studies and linked publications are excluded from the copied evidence rights grant.

The review interface and decision model were ported at file level from private PR #64, revision `38a4fa2`. No private question JSON, history, reviewer decisions or approval stamps were imported. The public snapshot has its own repository identity, snapshot hash and per-row content fingerprints. Eight question rows and one opening/closing row must all be current before signoff. Every exposed statement, reveal, takeaway, patient-conversation line, cue and closing text is visible to Kevin. Headers and facilitation instructions are explicitly classified separately from factual claims.

Question, answer-key, citation and evidence changes invalidate review fingerprints. Import rejects a different repository, a stale snapshot, unknown rows and stale row fingerprints. Approve, flag and skip support browser persistence and JSON handoff. These decisions are reviewer attestations, not cryptographic proof of the reviewer’s identity. Do not approve on Kevin’s behalf. `review:apply` stores a complete replacement snapshot, so undoing a decision removes it. `review:signoff` checks completeness but does not add a bank-wide clinical-review claim.

The all-correct and zero-correct bots replay independently transcribed fixed keys through the real evaluator and score function. Eight binary answers earn 800 base points, a 50 point bonus at three correct answers and a 100 point bonus at five, for 950 total. Every wrong answer scores zero and resets the streak. Neither speed nor confidence changes this total. The question IDs and display positions are varied in separate semantic checks.

The answer key is public in this repository and in the separate evidence and reviewer pages. This is a fixed public benchmark, not a blind test or protection against a participant deliberately browsing public answers. Isolation tests cover the participant runtime import graph and its pre-reveal wire payload. Host and solo assets intentionally contain keys. The review sheet is not imported or linked by the participant surface.

The human pilot is pending. Automated Chromium checks use synthetic participants and do not count as people, clinical review, assistive technology users or learning evidence. The prepared protocol uses one facilitator and four consenting adults across phone, keyboard and screen-reader paths. Findings will be reported only after actual attempts are recorded.
