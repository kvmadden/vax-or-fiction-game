Tasks and observations

  1. F1 follows Host this eight-question round from the evidence page, checks Influenza Insights and draft status, verifies audio is muted and the timer is off, and opens the lobby. Record completion, help and retries.
  2. Each player opens the join URL, enters the code and joins with a fictional nickname. Record success, failed joins, time, help and retries.
  3. Each player submits an answer and changes it before lock. Record the first and final choice, whether acknowledgement was understood, help and retries.
  4. F1 locks and reveals using only the keyboard. Each player identifies the answer through words rather than color or audio.
  5. Each player finds and opens a source after reveal. Keyboard and screen-reader players close the evidence view and confirm where focus returns. Record link discovery, accessibility barriers and confusion.
  6. One player reconnects before reveal. Check their answer state. F1 pauses for discussion, then resumes without time pressure. Record lost work, duplicate counts and retries.
  7. Finish all eight questions. Each player identifies the final score and the pending review boundary. Record errors or confusion without interpreting this as learning.

Recording rules

For every assigned task, record participant ID, task ID, attempted yes or no, completed without help, completed with help, failed or stopped, retries, elapsed time if measured, and a brief nonidentifying observation. Count an assigned but unattempted task separately. Report completions over actual attempts per task and device path. Do not convert four players into population percentages. Keep screen-reader findings separate from automated checks.

Record facilitator tasks separately from player tasks. Report failed joins over join attempts, changed answers over change attempts, source discoveries over source tasks, reconnect successes over reconnect attempts, and confusion and retry counts with their denominators. Report missing data as missing, not success. Keep the first run and later regression runs separate.

Stopping and follow-up

Stop the affected path if joining, voting, revealing or accessing evidence is blocked. Record the full failure and resume only after the participant agrees. Sort failures by wrong or stale claim, leaked answer, blocked participation and stable ID. Preserve every observation. Report a small pilot as usability observations with no learning-effectiveness claim.
